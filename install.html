LooperDisplay
☕ Kaffee spendieren

LooperDisplay ist ein Tool, das die ersten acht Looper in einem Ableton-Projekt erkennt und ihren Zustand als drehende Ringe in einer Weboberfläche visualisiert, die über das Intranet auch auf anderen Endgeräten (iPad, iPhone etc.) funktioniert.

Über diese Weboberfläche lassen sich die Looper auch direkt bedienen — antippen, dazu Stop und Clear über die Eck-Tasten. Dafür sind nur ein paar MIDI-Zuweisungen in Live nötig, den Rest übernimmt automatisch das Remote Script.

Zusätzlich und optional lassen sich die Looper auch über echte Hardware bedienen: über ein KORG nanoKONTROL2 (mit LED-Rückmeldung) und/oder ein Roland SPD-SX PRO (per Pad). Beide lösen dieselben Zuweisungen aus wie die Bedienung im Browser und dürfen gleichzeitig laufen.

Installation

Die App ist ein fertig gebautes Programm für Apple-Silicon-Macs (M-Prozessoren). Kein Node.js, kein npm install, kein Terminal-Wissen nötig.

3 App starten

Im Finder zu diesem Ordner wechseln und dort doppelklicken auf Looper-Display starten.command.

  1. Beim allerersten Mal blockiert macOS das mit „kann nicht geöffnet werden, da der Entwickler nicht verifiziert werden kann". Das ist normal bei selbst gebauten Programmen ohne teures Apple-Zertifikat.
  2. Im Finder mit Rechtsklick auf die Datei → „Öffnen" → im Dialog noch einmal „Öffnen" bestätigen. Das genügt einmalig, danach funktioniert der normale Doppelklick.
  3. Kurz erscheint ein Terminal-Fenster, minimiert sich dann von selbst, und ein Browser-Tab mit der Anzeige öffnet automatisch.

Beim allerersten Start fragt macOS zusätzlich einmalig, ob „osascript" das Terminal steuern darf — dafür wird das Fenster minimiert und später wieder geschlossen. Bitte erlauben. Ohne diese Erlaubnis läuft die App trotzdem, das Fenster bleibt dann nur offen.

Für ein Tablet zusätzlich die zweite, im (minimierten) Terminal-Fenster angezeigte Adresse dort in Safari öffnen:

Anzeige: http://localhost:8080
         http://192.168.0.XXX:8080  (für Tablet/Handy)

4 Auf dem Tablet einrichten (optional)

Für eine Anzeige ganz ohne Browser-Oberfläche: die zweite Adresse in Safari öffnen, Teilen-Symbol → „Zum Home-Bildschirm" — nicht „Zu Lesezeichen hinzufügen". Danach startet die Seite über das neue Symbol komplett ohne Adressleiste.

Wie beendest du es wieder?

Im Finder doppelklicken auf Looper-Display beenden.command — findet und beendet die App, auch wenn das (minimierte) Terminal-Fenster längst aus den Augen ist. Zwei weitere, gleichwertige Wege: ⏻ Server beenden oben rechts in der Anzeige selbst, oder Ctrl + C im (wieder eingeblendeten) Terminal-Fenster.

Schließt du nur den Browser-Tab mit der Anzeige, läuft die App im Hintergrund weiter — das ist meistens gewollt, falls ein Tablet die Seite dauerhaft offen halten soll.

Einzelne Looper aus dem Browser steuernoptional▶

Jeder Ring lässt sich antippen, dazu gibt es Tasten für Stop und Clear. Das braucht — anders als die vier Transporttasten oben in der Anzeige — eine kleine einmalige Einrichtung, weil Ableton Loopern keinen direkten „stoppe quantisiert" oder „lösche" Befehl über die API erlaubt. Der Weg dahin: ein virtueller MIDI-Bus, den die App bedient, und eine ganz normale MIDI-Zuweisung in Live.

  1. Audio-MIDI-Setup öffnen (Spotlight-Suche), Fenster „MIDI-Studio" einblenden, doppelt auf „IAC-Treiber" klicken, „Gerät ist online" anhaken. Ein Bus reicht.
  2. In Live, bei den MIDI-Ports: Eingang IAC-Treiber (Bus 1) — Remote an, Track aus.
  3. Cmd + M in Live (Map-Modus). Für jeden Looper: großen Transportknopf anklicken, kurz im Browser auf den Ring tippen — Zuweisung entsteht automatisch. Ebenso für die STOP- und CLEAR-Ecktasten.
  4. Cmd + M verlassen, Set speichern.

Live quantisiert danach selbst, genau wie bei einem echten Controller.

Die 24 Zuweisungen für Transport, Stop, ClearReferenz▶

Der State-Parameter des Loopers ließe sich auch direkt per API setzen — das umgeht aber die Quantisierung. Clear ist über die API außerdem gar nicht erreichbar. Beides läuft deshalb über Lives eigenes MIDI-Mapping, das den echten Knopf drückt und selbst sample-genau quantisiert:

BedienelementCCZiel im Looper
R 1–8 am nanoKONTROL264–71der große Transportknopf
S 1–8 am nanoKONTROL232–39Stop
M 1–8 am nanoKONTROL248–55Clear

Die Zuweisung hängt an der Nachricht, nicht am Port: Das SPD-Script sendet dieselben CCs auf Kanal 1 in den IAC-Treiber, der Browser über den Looper-Display-Server ebenso — alle drei Wege treffen dieselben 24 Zuweisungen.

  1. Cmd + M — MIDI-Map-Modus.
  2. Großen Transportknopf von Looper 1 anklicken, R1 drücken → CC 64.
  3. Stop-Knopf von Looper 1 anklicken, S1 drücken → CC 32.
  4. Clear-Button von Looper 1 anklicken, M1 drücken → CC 48.
  5. Für Looper 2 bis 8 dasselbe mit R2/S2/M2 … R8/S8/M8.
  6. Cmd + M verlassen, Set speichern — am besten als Standard-Set.

⚠️ Solange der Map-Modus aktiv ist und ein Element ausgewählt, legt jede eingehende MIDI-Nachricht eine neue Zuweisung an. R1, S1 und M1 gehören außerdem fest zu Looper 1: Lives Mapping folgt den Bank-Tasten des Pults nicht, nur die Fader tun das.

Grenzen

  • Status Looper leerverrät die Live-API nicht — die Anzeige weiß es nur aus eigener Messung oder einem Klick. Nach einem Sammelstart über Hardware (alle Looper gleichzeitig, unquantisiert über den State-Parameter) stehen auch leere Looper auf „Play" und sind vorübergehend nicht von gefüllten zu unterscheiden
  • NetzwerkApp und Live müssen im selben Netz laufen, sie hört per UDP mit — das geht nicht über das Internet

LooperDisplay is a tool that detects the first eight loopers in an Ableton project and visualizes their state as spinning rings in a web interface that also works over the local network on other devices (iPad, iPhone, etc.).

That web interface can also control the loopers directly — tap a ring, plus Stop and Clear via the corner buttons. That only needs a few MIDI mappings in Live; the Remote Script handles the rest automatically.

On top of that, and optionally, the loopers can also be played from real hardware: a KORG nanoKONTROL2 (with LED feedback) and/or a Roland SPD-SX PRO (by pad). Both trigger the same mappings as browser control and can run at the same time.

In Finder, double-click Looper-Display beenden.command — it finds and stops the app even if the (minimized) Terminal window is long out of sight. Two more, equally good ways: ⏻ Server beenden in the top right of the display itself, or Ctrl + C in the (restored) Terminal window.

Closing just the browser tab showing the display leaves the app running in the background — usually what you want if a tablet is meant to keep the page open permanently.

Controlling individual loopers from the browseroptional▶

Each ring can be tapped, and there are buttons for Stop and Clear too. Unlike the four transport buttons at the top of the display, this needs a small one-time setup, because Ableton doesn't offer a direct "quantised stop" or "clear" command through its API for loopers. The way around that: a virtual MIDI bus the app talks to, and an entirely ordinary MIDI mapping in Live.

  1. Open Audio MIDI Setup (Spotlight search), show the „MIDI Studio" window, double-click „IAC Driver", tick „Device is online". One bus is enough.
  2. In Live's MIDI ports: input IAC Driver (Bus 1) — Remote on, Track off.
  3. Cmd + M in Live (Map Mode). For each looper: click the big transport knob, then briefly tap the ring in the browser — the mapping is created automatically. Do the same for the STOP and CLEAR corner buttons.
  4. Leave Cmd + M, save the set.

Live then quantises everything itself, exactly as with a real controller.

The rings

Each looper has two rings: the outer one shows progress across the whole loop length with one mark per bar, the inner one is a pie that fills up once per bar. The centre shows bar / total bars and the state.

Controls in the browser

  • Tap the inner circlethe looper's transport button — Record, Play or Overdub, depending on state
  • Tap twice, quicklystops the looper — Ableton itself treats two quick clicks as a "double-click to stop"
  • Press and hold (0.6 s)cycle the bar count by hand (1, 2, 4, 8, 16) when the length is unknown
  • Corner button STOPbottom left of the ring — the same stop, as its own button
  • Corner button CLEARbottom right of the ring — clears the looper
  • Key F / "Fullscreen" buttontoggle fullscreen

  • "⏻ Server beenden" (Stop server)stops the Node server, after confirming — starting it again only works at the computer itself

Live only executes Stop and the transport button on the next bar line. Until then, the tapped spot pulses brightly with „WAITING".

The 24 mappings for Transport, Stop, Clearreference▶

The looper's State parameter could also be set directly through the API — but that bypasses quantisation. Clear also isn't reachable through the API at all. Both therefore run through Live's own MIDI Mapping, which presses the real button and quantises itself, sample-accurately:

The mapping is tied to the message, not the port: the SPD script sends the same CCs on channel 1 into the IAC driver, and so does the browser via the LooperDisplay server — all three paths hit the same 24 mappings.

  1. Cmd + M — MIDI Map Mode.
  2. Click looper 1's big transport knob, press R1 → CC 64.
  3. Click looper 1's Stop button, press S1 → CC 32.
  4. Click looper 1's Clear button, press M1 → CC 48.
  5. Repeat for loopers 2 through 8 with R2/S2/M2 … R8/S8/M8.
  6. Leave Cmd + M, save the set — ideally as the default set.

⚠️ While Map Mode is active and an element is selected, every incoming MIDI message creates a new mapping. R1, S1 and M1 are also fixed to looper 1: Live's mapping doesn't follow the controller's bank buttons, only the faders do.

Before you ask

Limitations

  • Looper-empty statusthe Live API doesn't reveal this — the display only knows it from its own measurement or a manual click. After a hardware group start (all loopers at once, unquantised via the State parameter), empty loopers also show as „Play" and are briefly indistinguishable from full ones
  • Networkthe app and Live must be on the same network, it listens over UDP — this doesn't work over the internet
  • Architecturetested on Apple Silicon Macs; for Intel Macs or Windows, please get in touch
